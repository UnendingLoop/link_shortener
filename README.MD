# URL Shortener Service

Backend-сервис для сокращения ссылок с поддержкой аналитики переходов.

Проект реализует:
- создание коротких ссылок(наподобие сервиса bit.ly/abc123);
- редирект клиентов;
- сбор статистики переходов(логирование user-agent и времени запроса);
- агрегацию аналитики по дням, месяцам и user-agent;
- простой web-интерфейс для взаимодействия с API.

---

## Стек

- Golang 1.24;
- PostgreSQL;
- In-memory cache (Redis);
- HTTP API;
- Docker / docker-compose;
- HTML + JS (UI).

---

## Архитектура

Проект построен по слоистой архитектуре:

```json
handler → service → repository → database
            ↓
          cache
```

### Слои

- **model**  
  Хранилище описания всех структур данных, используемых приложением.

- **handler**  
  HTTP-обработчики - oтвечают за:
  - парсинг входных данных;
  - валидацию query-параметров;
  - формирование HTTP-ответов.

- **service**  
  Бизнес-логика приложения:  
  - проверка корректности данных;
  - маршрутизация сценариев;
  - работа с ошибками:
    - логирование технических ошибок;
    - передача user-friendly ошибок в слой хендлера.

- **repository**  
  Доступ к данным (PostgreSQL).
  Содержит SQL-логику и маппинг данных.

- **cache**  
  In-memory (Redis) кеш для быстрых редиректов.

## Запуск проекта

### 1. Клонирование

```bash
git clone https://github.com/UnendingLoop/link_shortener
cd link_shortener
```

### 2. Запуск через Docker

```bash
docker-compose up --build
```

После запуска сервис будет доступен по адресу:
http://localhost:8080

## Web UI

Простой одностраничный интерфейс доступен по адресу:

http://localhost:8080/web/index.html

UI поддерживает:
- создание short-link
- просмотр списка всех ссылок
- просмотр аналитики по выбранной ссылке c применением:
    - типа аггрегации(по месяцу/дню/юзерагенту)
    - фильтра по дате(пустые даты так же валидны)

## HTTP API

### GET /ping

**Назначение:** базовая проверка живости приложения.
**Ответ:**

```json
{ "message": "pong" }
```

### Создание короткой ссылки
POST /shorten

**Назначение:** Создание и сохранение связки ключа(короткая ссылка) и значения(ссылка для редиректа). 
У пользователя есть возможность задать собственную короткую ссылку, если она еще не зарегистрирована в БД.

**Тело запроса:**

```json
{
  "shortkey": "mykey",   // optional
  "redirect": "https://example.com"
}
```

**Ответ:**

```json
{
  "shortkey": "mykey",
  "redirect": "https://example.com",
  "created_at": "2025-01-01T12:00:00Z"
}
```

### Редирект 

GET /s/:short_url

Назначение: перенаправление клиентов на адрес, соответсвующий короткой ссылке в БД.
**Ответ:**

```bash
HTTP 301 Redirect
```

### Получение всех ссылок

GET /shorten/all?limit=20&offset=0

**Назначение:** получение всех ранее созданных коротких ссылок со сыллкой редиректа и временм создания.

**Ответ:** 

```json
[
    {
        "shortkey": "example1",
        "redirect": "https://exampleweb.com",
        "created_at": "2025-12-24T16:55:41.723644Z"
    },
    ...
    {
        "shortkey": "example2",
        "redirect": "https://exampleweb.com",
        "created_at": "2025-12-24T17:55:16.105362Z"
    }
]
```

### Аналитика
GET /analytics/:short_url

**Назначение:** запрос и получение накопленной аналитики по выбранной короткой ссылке с возможностью указания типа аггрегации: 
- по дням, 
- по месяцам 
- или по юзерагенту

**Query-параметры:**

```
Параметр	Описание
grouping	day / month / useragent
start	дата начала (YYYY-MM-DD), less than end, optional
end	дата окончания (YYYY-MM-DD), more that start, optional
limit	лимит записей
offset	смещение
```
**Пример запроса:**

GET /analytics/abc123?grouping=useragent&start=2025-01-01&end=2025-01-31

**Ответ:**

```json
{
  "groupby": "by useragent",
  "total": 4,
  "items": [
    {
      "line": "Chrome/Windows",
      "count": 3
    },
    {
      "line": "Edge/Windows",
      "count": 1
    }
  ]
}
```

go test ./...
